# 第三章 问题建模与系统总体框架

---

## 3.1 系统场景描述

考虑车联网（VEC）边云协同推理场景：车载终端（Edge Device）配备有限算力的处理器，路侧单元（RSU）或移动边缘计算（MEC）服务器提供云端高性能GPU算力。车辆上运行的DNN推理任务（如目标检测、行人识别）需要在时延约束内完成。

系统由以下组件构成：
- **边端设备**（Edge）：车载域控制器，计算能力有限
- **云端设备**（Cloud）：MEC服务器，配备GPU，计算能力强
- **无线信道**：车辆与RSU之间的通信链路，带宽动态变化

## 3.2 DNN模型分割建模

### 3.2.1 层级表示

将DNN模型 $\mathcal{M}$ 表示为 $L$ 个可计算层的有序序列：

$$\mathcal{M} = \{l_1, l_2, \ldots, l_L\}$$

其中每一层 $l_i$ 可以是卷积层（Conv）、全连接层（FC）或其他操作层（如池化、激活等）。

### 3.2.2 分割点定义

定义分割点 $p \in \{0, 1, 2, \ldots, L\}$，其含义为：
- 层 $l_1$ 至 $l_p$ 在**边端**执行
- 层 $l_{p+1}$ 至 $l_L$ 在**云端**执行
- 特别地，$p = 0$ 表示全部云端推理，$p = L$ 表示全部本地推理

分割后，边端在第 $p$ 层输出中间特征张量 $\mathbf{F}_p$，其数据大小为 $D_p$（单位：MB）。

## 3.3 延迟模型

### 3.3.1 边端推理延迟

边端推理延迟为前 $p$ 层在边端设备上的执行时间：

$$T_{\text{edge}}(p) = \sum_{i=1}^{p} t_i^{\text{edge}}$$

其中 $t_i^{\text{edge}}$ 为第 $i$ 层在边端的推理延迟。由于边端算力有限，不同层类型的计算延迟不同：

$$t_i^{\text{edge}} = \begin{cases} \alpha_{\text{conv}} \cdot t_i^{\text{cloud}} & \text{if } l_i \text{ is Conv layer} \\ \alpha_{\text{fc}} \cdot t_i^{\text{cloud}} & \text{if } l_i \text{ is FC layer} \\ \alpha_{\text{other}} \cdot t_i^{\text{cloud}} & \text{otherwise} \end{cases}$$

其中 $\alpha_{\text{conv}}, \alpha_{\text{fc}}, \alpha_{\text{other}}$ 分别为卷积层、全连接层和其他层的边云计算速度比（$\alpha > 1$ 表示边端更慢）。$t_i^{\text{cloud}}$ 为第 $i$ 层在云端的参考推理延迟。

### 3.3.2 传输延迟

中间特征 $\mathbf{F}_p$ 经压缩后的传输延迟为：

$$T_{\text{trans}}(p, r) = \frac{D_p \cdot r}{B}$$

其中：
- $D_p$ 为第 $p$ 层输出的中间特征原始大小（MB）
- $r \in [r_{\min}, 1]$ 为压缩率（保留比例），$r_{\min} = 0.2$
- $B$ 为当前可用带宽（MB/s）

特别地，当 $p = 0$ 时（全部云端），传输原始输入数据：$T_{\text{trans}}(0, r) = D_{\text{input}} / B$；当 $p = L$ 时（全部本地），无需传输：$T_{\text{trans}}(L, r) = 0$。

### 3.3.3 云端推理延迟

云端推理延迟为后 $(L-p)$ 层在云端的执行时间：

$$T_{\text{cloud}}(p) = \sum_{i=p+1}^{L} t_i^{\text{cloud}}$$

### 3.3.4 端到端推理延迟

总推理延迟为三部分之和：

$$T_{\text{total}}(p, r, B) = T_{\text{edge}}(p) + T_{\text{trans}}(p, r) + T_{\text{cloud}}(p)$$

## 3.4 压缩模型

### 3.4.1 结构化通道剪枝

对于卷积层输出的中间特征 $\mathbf{F}_p \in \mathbb{R}^{N \times C \times H \times W}$，采用结构化通道剪枝压缩。给定压缩率 $r$，保留 $\lfloor C \cdot r \rfloor$ 个最重要的通道：

1. 计算每个通道 $c$ 的重要性分数（L2范数）：
$$s_c = \left\| \mathbf{F}_p[:, c, :, :] \right\|_2$$

2. 按重要性降序排列，保留 top-$k$ 通道（$k = \lfloor C \cdot r \rfloor$）：
$$\mathcal{K} = \text{top-}k(\{s_1, s_2, \ldots, s_C\})$$

3. 生成压缩特征：
$$\mathbf{F}_p^{\text{comp}} = \mathbf{F}_p[:, \mathcal{K}, :, :] \in \mathbb{R}^{N \times k \times H \times W}$$

### 3.4.2 全连接层剪枝

对于全连接层输出 $\mathbf{F}_p \in \mathbb{R}^{N \times D}$，按神经元激活值的L1范数排序，保留 $\lfloor D \cdot r \rfloor$ 个最重要的神经元。

### 3.4.3 压缩后的数据量

压缩后实际传输的数据量为：

$$D_p^{\text{comp}}(r) = D_p \cdot r + D_{\text{mask}}$$

其中 $D_{\text{mask}}$ 为保留通道/神经元的索引掩码（通常远小于特征数据本身，可忽略）。

### 3.4.4 云端特征恢复

在云端接收到压缩特征 $\mathbf{F}_p^{\text{comp}}$ 和掩码 $\mathcal{K}$ 后，通过零填充恢复原始维度：

$$\hat{\mathbf{F}}_p[:, c, :, :] = \begin{cases} \mathbf{F}_p^{\text{comp}}[:, c, :, :] & \text{if } c \in \mathcal{K} \\ \mathbf{0} & \text{otherwise} \end{cases}$$

恢复后的 $\hat{\mathbf{F}}_p$ 可直接输入云端模型的后续层进行推理。

## 3.5 准确率模型

压缩导致部分特征信息丢失，影响模型推理准确率。基于结构化剪枝的经验模型，准确率下降可建模为：

$$A(p, r) = A_0 \cdot (1 - k_p \cdot \sigma(-s_p \cdot (r - c_{0,p})))$$

其中：
- $A_0$ 为无压缩时的基准准确率
- $k_p$ 为在分割点 $p$ 处的最大准确率下降幅度，由层类型和层位置决定
- $s_p$ 为sigmoid衰减的陡度
- $c_{0,p}$ 为衰减中心点（CR低于该值时准确率开始显著下降）
- $\sigma(\cdot)$ 为sigmoid函数

层位置对压缩的鲁棒性不同：
- 模型前端层（浅层特征）对压缩更敏感（$k_p$ 较大）
- 模型后端层（高级语义特征）对适度压缩更鲁棒（$k_p$ 较小）

## 3.6 优化问题形式化

### 3.6.1 联合优化目标

给定当前网络带宽 $B$ 和系统状态，目标是找到最优的分割点 $p^*$ 和压缩率 $r^*$，使得推理延迟最小化同时准确率满足约束：

$$\min_{p, r} \quad T_{\text{total}}(p, r, B)$$
$$\text{s.t.} \quad A(p, r) \geq A_{\text{th}}$$
$$\quad\quad p \in \mathcal{P}_{\text{feasible}}$$
$$\quad\quad r \in [r_{\min}, 1.0]$$

其中 $A_{\text{th}}$ 为准确率下限阈值，$\mathcal{P}_{\text{feasible}}$ 为经过预筛选的可行分割点集合。

### 3.6.2 问题复杂性分析

该优化问题具有以下特征：
1. **混合变量**：分割点 $p$ 为离散变量，压缩率 $r$ 为连续变量
2. **动态环境**：带宽 $B$ 随时间变化，需要在线决策
3. **非凸性**：延迟和准确率关于 $(p, r)$ 的映射是非凸的
4. **多目标**：需要同时优化延迟和准确率，二者之间存在 trade-off

传统的静态搜索方法（如Neurosurgeon的贪心策略）无法处理动态带宽和压缩率的联合优化。因此，本文将该问题建模为马尔可夫决策过程（MDP），并采用强化学习方法求解。

## 3.7 MDP建模

将协同推理决策问题建模为MDP $(\mathcal{S}, \mathcal{A}, P, R, \gamma)$：

### 3.7.1 状态空间 $\mathcal{S}$

状态向量 $\mathbf{s}_t \in \mathbb{R}^5$，归一化至 $[0, 1]$：

$$\mathbf{s}_t = \left( \frac{T_{\text{total}}^{t-1}}{T_{\text{local}}}, \frac{B_t}{B_{\max}}, \frac{A^{t-1}}{A_0}, \frac{D_{p}^{t-1}}{D_{\max}}, \frac{T_{\text{edge}}^{t-1}}{T_{\text{total}}^{t-1}} \right)$$

各分量含义：
| 分量 | 含义 | 说明 |
|------|------|------|
| $s_1$ | 归一化延迟 | 上一步延迟 / 最大延迟 |
| $s_2$ | 归一化带宽 | 当前带宽 / 最大带宽 |
| $s_3$ | 归一化准确率 | 上一步准确率 / 基准准确率 |
| $s_4$ | 归一化特征大小 | 中间特征大小 / 最大特征大小 |
| $s_5$ | 边端负载比 | 边端延迟 / 总延迟 |

### 3.7.2 动作空间 $\mathcal{A}$

混合动作空间 $\mathcal{A} = \mathcal{A}_d \times \mathcal{A}_c$：

- **离散动作** $a_d \in \mathcal{A}_d = \{1, 2, \ldots, |\mathcal{P}_{\text{feasible}}|\}$：选择可行分割点集合中的某个分割点
- **连续动作** $a_c \in \mathcal{A}_c = [r_{\min}, 1.0]$：确定压缩率

### 3.7.3 奖励函数 $R$

$$R(\mathbf{s}_t, \mathbf{a}_t) = -w_l \cdot \min\left(\frac{T_{\text{total}}}{T_{\text{local}}}, \tau_{\max}\right) + w_a \cdot \frac{A(p, r)}{A_0} - \lambda \cdot \max\left(0, \frac{A_{\text{th}} - A(p,r)}{A_0}\right)$$

其中：
- $w_l, w_a$ 分别为延迟和准确率的权重（$w_l + w_a = 1$）
- $T_{\text{local}}$ 为纯本地推理延迟，作为归一化参考
- $\tau_{\max}$ 为延迟比上限截断（防止极端值）
- $\lambda$ 为准确率约束惩罚系数

该奖励函数的设计使得：
- 初始随机探索时（选到高延迟分割点），$T_{\text{total}} / T_{\text{local}} \gg 1$，奖励为负
- 训练收敛后（找到最优策略），$T_{\text{total}} / T_{\text{local}} < 1$，奖励为正
- 准确率大幅下降时触发额外惩罚，防止过度压缩

### 3.7.4 状态转移

$$\mathbf{s}_{t+1} = f(\mathbf{s}_t, \mathbf{a}_t, B_{t+1})$$

其中带宽 $B_{t+1}$ 由环境动态决定，模拟车联网中带宽随车速、信号覆盖变化的特点。

## 3.8 分区点预筛选算法

为缩小RL智能体的离散动作空间，加速训练收敛，提出基于延迟-准确率双重约束的分区点预筛选算法。

### 算法原理

从全部 $|\mathcal{P}| = L + 1$ 个候选分割点中，通过以下两轮筛选保留 $25\%$ 至 $50\%$ 的可行分割点：

1. **延迟筛选**：以中位延迟为基准，保留延迟不超过 $\text{median} \times (1 + \delta_l)$ 的分割点
2. **准确率筛选**：若可行点仍过多，按准确率降序排列并丢弃准确率下降超过阈值的点
3. **自适应阈值调整**：若筛选后点数不在目标范围内，迭代调整阈值直到满足

---

### Algorithm 1: Partition Point Pre-Filtering (分区点预筛选)

```
Algorithm 1: Partition Point Pre-Filtering
─────────────────────────────────────────────────────
Input:
    M: DNN模型, L: 总层数, B: 参考带宽
    r_d: 默认压缩率 (0.8), A_0: 基准准确率
Output:
    P_feasible: 可行分割点集合

1:  P_all ← {0, 1, ..., L}                        ▷ 全部候选分割点
2:  n_min ← max(3, ⌈|P_all| × 0.25⌉)             ▷ 最少保留点数
3:  n_max ← ⌊|P_all| × 0.50⌋                      ▷ 最多保留点数
4:  for each p ∈ P_all do
5:      lat_p ← T_total(p, r_d, B)                 ▷ 计算延迟
6:      acc_p ← A(p, r_d)                           ▷ 计算准确率
7:  end for
8:  lat_median ← Median({lat_p | p ∈ P_all})
9:  δ_l ← 0.25; δ_a ← 0.02                        ▷ 初始阈值
10: P_feasible ← P_all

11: for iter = 1, 2, ..., max_iter do
12:     ▷ Step 1: 延迟筛选
13:     limit ← lat_median × (1 + δ_l)
14:     P_lat ← {p ∈ P_feasible | lat_p ≤ limit}
15:     if |P_lat| < n_min then
16:         δ_l ← δ_l + 0.05                       ▷ 放宽延迟约束
17:         continue
18:     end if
19:     P_feasible ← P_lat

20:     if |P_feasible| ≤ n_max then
21:         break                                    ▷ 已在目标范围内
22:     end if

23:     ▷ Step 2: 准确率筛选
24:     Sort P_feasible by acc_p descending
25:     acc_best ← max({acc_p | p ∈ P_feasible})
26:     P_acc ← {p ∈ P_feasible | acc_best - acc_p ≤ δ_a}
27:     if |P_acc| < n_min then
28:         P_acc ← top n_min points from P_feasible by acc_p
29:     end if
30:     P_feasible ← P_acc

31:     if |P_feasible| ≤ n_max then
32:         break
33:     end if

34:     ▷ Step 3: 收紧阈值
35:     δ_l ← max(0.05, δ_l - 0.05)
36:     δ_a ← max(0.005, δ_a - 0.002)
37: end for

38: return P_feasible
```

### Algorithm 2: Hybrid PPO Training (混合PPO训练)

```
Algorithm 2: Hybrid PPO for ARL-Comp
─────────────────────────────────────────────────────
Input:
    M: DNN模型, P_feasible: 可行分割点集合

    ε: PPO裁剪系数, γ: 折扣因子, λ_GAE: GAE参数

    π*: 训练好的策略网络

2:  Initialize Critic network V_φ
3:  Initialize entropy coefficient β ← β_0

4:  for episode = 1, 2, ..., N_ep do
5:      s ← env.reset()                            ▷ 随机带宽初始化
6:      D ← ∅                                       ▷ 清空轨迹缓冲区
7:      ▷ 熵系数线性衰减
8:      β ← β_0 + (β_final - β_0) × episode / N_ep

9:      for step = 1, 2, ..., N_step do
10:         ▷ Actor输出混合动作

18:         p ← P_feasible[a_d]                      ▷ 映射到实际分割点

24:                    log Beta(a_c|α,β_B), R, done, v)}
25:         s ← s'
26:     end for

27:     ▷ PPO更新
28:     Compute GAE advantages {Â_t} and returns {G_t}
29:     for update_epoch = 1, ..., K do
30:         for mini-batch B ⊂ D do
31:             ▷ 重新计算新策略下的log概率
32:             π_d^new, α^new, β_B^new ← π_θ(s_B)
33:             log_π_d^new ← log Categorical(a_d | π_d^new)
34:             log_π_c^new ← log Beta(a_c | α^new, β_B^new)

35:             ▷ 计算重要性比率
36:             ρ ← exp((log_π_d^new + log_π_c^new)
37:                   - (log_π_d^old + log_π_c^old))

38:             ▷ PPO Clipped Objective
39:             L_clip ← min(ρ·Â, clip(ρ, 1-ε, 1+ε)·Â)

40:             ▷ Actor损失 (含熵正则)
41:             H ← H(Categorical) + H(Beta)          ▷ 熵
42:             L_actor ← -L_clip - β·H

43:             ▷ Critic损失
44:             L_critic ← MSE(V_φ(s_B), G_B)

45:             ▷ 梯度更新
46:             θ ← θ - η_a · ∇_θ L_actor
```

### Algorithm 3: ARL-Comp Inference (ARL-Comp推理流程)

```
Algorithm 3: ARL-Comp Online Inference
─────────────────────────────────────────────────────
Input:
    x: 输入数据, M: DNN模型, π*: 训练好的策略
    B: 当前带宽, s: 当前状态
Output:
    ŷ: 推理结果

1:  ▷ Step 1: 策略决策
2:  (p*, r*) ← π*(s)                              ▷ 确定性输出

3:  ▷ Step 2: 边端推理
4:  F_p ← M[1:p*](x)                              ▷ 前p*层在边端执行

5:  ▷ Step 3: 特征压缩
6:  F_comp, mask ← Compress(F_p, r*)               ▷ 结构化剪枝

7:  ▷ Step 4: 传输
8:  Send (F_comp, mask) to Cloud via wireless channel

9:  ▷ Step 5: 云端恢复与推理
10: F̂_p ← Restore(F_comp, mask)                    ▷ 零填充恢复
11: ŷ ← M[p*+1:L](F̂_p)                            ▷ 后续层在云端执行

12: ▷ Step 6: 状态更新
13: s' ← UpdateState(T_total, A, B, ...)

14: return ŷ
```

## 3.9 系统总体框架

ARL-Comp 系统的总体框架包含三个核心模块：

### 3.9.1 离线训练阶段

1. **模型 Profiling**：对DNN各层进行性能分析，获取逐层计算延迟和中间特征大小
2. **分区点预筛选**：通过 Algorithm 1 缩小可行分割点集合
3. **RL策略训练**：在模拟环境中使用 Algorithm 2 训练 Hybrid PPO 智能体

### 3.9.2 在线推理阶段

1. **状态感知**：获取当前带宽、历史延迟/准确率等状态信息
2. **策略决策**：通过训练好的策略网络输出分割点和压缩率
3. **协同推理执行**：按 Algorithm 3 执行边端推理 → 特征压缩 → 传输 → 云端恢复 → 云端推理

### 3.9.3 特征压缩与恢复模块

- **边端**：对中间特征执行结构化通道剪枝，仅传输保留的通道数据和索引掩码
- **云端**：根据掩码进行零填充恢复，确保后续层的输入维度匹配
- 压缩率由RL智能体动态决定，在传输效率和信息保真之间取得平衡
