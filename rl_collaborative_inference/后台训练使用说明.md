# 后台训练使用说明

## 概述

为了支持长时间训练（500K步可能需要数小时到数天），我们提供了后台训练功能，支持：
- 后台运行训练任务
- 日志记录和查看
- 进程管理和监控
- 任务停止和恢复

## 快速开始

### 方法1：使用Python脚本（推荐）

#### 启动后台训练

```bash
cd rl_collaborative_inference

# 启动对比实验

    --script train_with_tracking.py \
    --job_name comparison_experiment \
    --data_dir ../data/caltech-101 \
    --output_dir ./experiments/comparison \
    --max_steps 500000 \
    --use_cuda

# 启动超参数敏感性实验（所有实验）

    --data_dir ../data/caltech-101 \
    --output_dir ./experiments/hyperparameter_sensitivity \
    --experiment all \
    --use_cuda
```

#### 查看训练状态

```bash
# 查看所有任务状态
python run_training_background.py status

# 查看特定任务状态
python run_training_background.py status comparison_experiment
```

#### 查看日志

#### 停止训练

```bash

# 停止所有任务

```

## 详细说明

### 1. 启动后台训练

#### 基本用法

```bash
python run_training_background.py start \
    --script <训练脚本> \
    --job_name <任务名称> \
    --data_dir <数据集路径> \
    [其他参数...]
```

#### 参数说明

- `--script`: 训练脚本路径（如 `train_with_tracking.py`）
- `--job_name`: 任务名称，用于标识和管理（可选，默认自动生成）
- `--data_dir`: 数据集路径（必需）
- `--output_dir`: 输出目录（默认：`./results`）
- `--max_steps`: 最大训练步数（默认：500000）
- `--lr_actor`: Actor学习率（默认：0.0001）
- `--lr_critic`: Critic学习率（默认：0.0001）
- `--k_epochs`: 更新轮数（默认：10）
- `--batch_size`: 批次大小（默认：64）
- `--network_bandwidth`: 网络带宽（默认：10.0）
- `--seed`: 随机种子（可选）
- `--use_cuda`: 使用CUDA（如果可用）
- `--log_dir`: 日志目录（默认：`./logs`）

#### 示例

```bash
# 启动一个完整的对比实验
python run_training_background.py start \
    --script train_with_tracking.py \
    --job_name comparison_experiment \
    --data_dir ../data/caltech-101 \
    --output_dir ./experiments/comparison \
    --max_steps 500000 \
    --lr_actor 0.0001 \
    --lr_critic 0.0001 \
    --k_epochs 10 \
    --batch_size 64 \
    --network_bandwidth 10.0 \
    --seed 42 \
    --use_cuda \
    --log_dir ./logs
```

### 2. 查看训练状态

```bash
# 查看所有任务
python run_training_background.py status

# 查看特定任务（包含最新日志）
python run_training_background.py status comparison_experiment
```

输出示例：
```

  PID: 12345
  Status: running
  Start time: 2024-01-01T10:00:00
  Log file: ./logs/comparison_experiment.log
```

### 3. 查看日志

```bash
# 查看最后50行（默认）
python run_training_background.py tail comparison_experiment

# 查看最后100行
python run_training_background.py tail comparison_experiment --lines 100

# 实时监控日志（使用tail命令）
tail -f ./logs/comparison_experiment.log
```

### 4. 停止训练

```bash
# 停止特定任务（优雅停止，会保存checkpoint）
python run_training_background.py stop comparison_experiment

# 停止所有任务
python run_training_background.py stop_all
```

**注意：** 停止训练时会先发送SIGTERM信号，等待5秒后如果进程仍在运行，会发送SIGKILL强制终止。

### 5. 超参数敏感性实验

```bash

    --experiment all \
    --use_cuda

    --data_dir ../data/caltech-101 \
    --output_dir ./experiments/hyperparameter_sensitivity \
    --experiment lr \
    --use_cuda

# 只运行重用时间实验
python experiments/run_hyperparameter_background.py \
    --data_dir ../data/caltech-101 \
    --output_dir ./experiments/hyperparameter_sensitivity \
    --experiment reuse_time \
    --use_cuda

# 只运行内存大小实验
python experiments/run_hyperparameter_background.py \
    --data_dir ../data/caltech-101 \
    --output_dir ./experiments/hyperparameter_sensitivity \
    --experiment memory_size \
    --use_cuda
```

## 日志文件

所有日志文件保存在 `./logs/` 目录下：

- `<job_name>.log`: 标准输出日志
- `<job_name>.err`: 错误输出日志
- `training_pids.json`: 进程ID记录文件

## 进程管理

### 进程ID文件

进程信息保存在 `./logs/training_pids.json` 中，包含：
- 进程ID (PID)
- 进程组ID (PGID)
- 启动时间
- 日志文件路径
- 命令
- 状态

### 手动检查进程

```bash
# 查看所有Python训练进程
ps aux | grep train_with_tracking.py

# 查看特定进程
ps -p <PID>

# 查看进程树
pstree -p <PID>
```

## 训练恢复

训练脚本支持checkpoint机制，如果训练中断：

1. 检查最新的checkpoint文件（在输出目录中）
2. 可以修改训练脚本支持从checkpoint恢复（需要添加恢复功能）

## 使用screen/tmux（可选）

如果需要更强大的会话管理，可以使用screen或tmux：

### 使用screen

```bash
# 创建新的screen会话
screen -S training

# 在screen中运行训练
python train_with_tracking.py --data_dir ../data/caltech-101 ...

# 分离会话：按 Ctrl+A 然后按 D
# 重新连接：screen -r training
# 列出所有会话：screen -ls
```

### 使用tmux

```bash
# 创建新的tmux会话
tmux new -s training

# 在tmux中运行训练
python train_with_training.py --data_dir ../data/caltech-101 ...

# 分离会话：按 Ctrl+B 然后按 D
# 重新连接：tmux attach -t training
# 列出所有会话：tmux ls
```

## 故障排除

### 问题1：进程无法启动

**检查：**
- Python环境是否正确
- 数据集路径是否存在
- 是否有足够的磁盘空间

### 问题2：进程意外终止

**检查：**
- 查看错误日志：`./logs/<job_name>.err`
- 检查系统资源（内存、磁盘）
- 检查CUDA内存（如果使用GPU）

### 问题3：无法停止进程

**解决方法：**
```bash
# 手动终止进程
kill -TERM <PID>

# 强制终止
kill -KILL <PID>

# 终止进程组
kill -TERM -<PGID>
```

### 问题4：日志文件过大

**解决方法：**
```bash
# 压缩旧日志
gzip ./logs/*.log

# 删除旧日志
find ./logs -name "*.log" -mtime +7 -delete
```

## 最佳实践

1. **使用有意义的任务名称**：便于管理和识别
2. **定期检查状态**：确保训练正常进行
3. **监控资源使用**：避免系统资源耗尽
4. **保存checkpoint**：定期保存模型检查点
5. **备份重要结果**：定期备份实验结果

## 示例工作流

```bash
# 1. 启动训练
python run_training_background.py start \
    --script train_with_tracking.py \
    --job_name my_experiment \
    --data_dir ../data/caltech-101 \
    --max_steps 500000 \
    --use_cuda

# 2. 检查状态
python run_training_background.py status

# 3. 监控日志（在另一个终端）
tail -f ./logs/my_experiment.log

# 4. 定期检查进度
python run_training_background.py status my_experiment

# 5. 训练完成后，停止任务（如果需要）
python run_training_background.py stop my_experiment
```

## 注意事项

1. **长时间训练**：500K步的训练可能需要数小时到数天，确保：
   - 系统不会自动休眠
   - 网络连接稳定（如果使用远程服务器）
   - 有足够的磁盘空间

2. **资源管理**：多个任务同时运行会消耗大量资源，注意：
   - GPU内存限制
   - 系统内存限制
   - CPU使用率

3. **日志管理**：长时间训练会产生大量日志，定期清理或压缩

4. **检查点保存**：确保checkpoint保存频率合理，避免磁盘空间不足
